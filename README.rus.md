# Fast Port Scanner

Высокоскоростной TCP-сканер IPv4-адресов и CIDR-сетей.

Создан для быстрого поиска доступных TCP-портов с простой CLI, высокой параллельностью и минимальными накладными расходами.

## Возможности

* TCP connect scanning
* IPv4-адреса и CIDR-сети
* Смешанный список IP и CIDR
* До 1 000 000 целей за один запуск
* Настраиваемый timeout подключения
* Настраиваемая параллельность
* Удаление дубликатов
* Отмена через Ctrl+C
* Отображение прогресса в реальном времени
* Сортировка результатов
* Без внешних зависимостей

## Использование

```text
fps.exe -i ip.txt -p 80
```

Доступные параметры:

```text
-i, --input        Input file with IPv4 addresses/CIDR
-p, --port         TCP port to scan
-o, --output       Output file (default: results.txt)
-t, --timeout      Connection timeout in ms (default: 500)
-c, --concurrency  Maximum concurrent connections (default: 2000)
-h, --help         Show this help
```

Пример:

```text
fps.exe -i ip.txt -p 80 -o results.txt -t 500 -c 2000
```

## Входные данные

Файл может содержать отдельные IPv4-адреса, CIDR-сети или их комбинацию:

```text
192.168.1.1
192.168.1.10
192.168.1.0/24
10.0.0.0/24
```

Поддерживаются комментарии:

```text
192.168.1.1 # router
10.0.0.0/24 # network
```

## Результат

В выходной файл записывается по одному IP-адресу на строку для хостов, на которых указанный TCP-порт принял подключение:

```text
192.168.1.1
192.168.1.10
192.168.1.25
```

## Производительность

Сканер рассчитан на высокоскоростное TCP-сканирование и использует асинхронные TCP-подключения с ограниченной параллельностью.

Пример реального теста:

```text
65 536 targets
TCP-порт: 500
Timeout: 500 мс
Concurrency: 2 000

Время: 17.39 с
```

Фактическое время сканирования сильно зависит от состояния сети, задержек, фильтрации и количества хостов, которые не отвечают.

## Примечания

* Сканер выполняет прямую TCP-попытку подключения. Предварительный ping не используется.
* Поддерживается только IPv4.
* Слишком маленький timeout может ускорить сканирование, но привести к пропуску медленных хостов.
* Увеличение concurrency может значительно ускорить сканирование, но оптимальное значение зависит от сети и системы.
